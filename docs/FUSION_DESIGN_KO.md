## 2. 비평 반영 내용

| 비평 | 반영 |
|---|---|
| ① 가중치의 의미 | R-GAT 출력 w는 CI의 **정보 가중치**로 정의한다. 실제 기여도와 융합 불확실성은 따로 계산·보고한다. 실제 기여도 c_k = tr(P_f w_k P_k⁻¹)/3이고, 합은 1이다. [구현·검증] `evaluate.py` |
| ② CI가 정확도를 보장하지 않음 | 정확도(RMSE·p95·최대·RTE)와 공분산 일관성(NEES, χ²₉₅ 초과 비율)을 독립 지표로 둔다. 표준 CI(최소 trace)와 균등 CI를 기준선으로 둔다. [구현·검증] |
| ③ 좌표계 정렬의 공통 오차 | 해들 사이 오차 상관을 분석해 1차 결과를 얻었다(4절). 전역 오차와 지역 오차(10 s 상대 오차 RTE)를 따로 평가한다. 정렬 유효·잔차·나이는 입력 특징으로 유지한다. |
| ④ 학습 가중치는 CI의 보수성을 보장하지 않음 | 주장하지 않는다. 비평의 반례(관측값에 의존하는 가중치)를 문서에 기록하고, 공분산 일관성은 실험으로만 판단한다. |
| ⑤ 온톨로지의 실제 기여 | 온톨로지가 융합 연산에 들어가는 지점은 세 곳이다. 아래 표 참조. 온톨로지 제약을 뺀 그래프(`ontology_constraints=False`)를 비교군으로 둔다. |
| 성분별 차이 | 해 × 블록(위치·속도·자세) 가중치를 쓰는 `head="block"` 변형을 둔다. [구현·검증: 기울기 전달] |
| 진행 순서 | 비평의 권장 순서를 따른다: 정렬·공분산 확인 → 표준 CI 대 선택 → GRU 가중치 → 온톨로지 R-GAT → 공통 센서·복합 결함 → 전체 상태·폐루프 |

온톨로지가 융합 연산에 들어가는 세 지점은 다음과 같다(`ijcas/fusion/ontology.py`).

| 온톨로지 관계 | 융합 연산에 미치는 영향 |
|---|---|
| 추정기의 입력 의존(`:requiresEssential`, `:usesAiding`) | R-GAT의 보호 간선(정의 관계 6개 + 해 → 융합 3개). 필수 입력의 수신 검사는 적격성에서 처리한다. |
| 공통 측정원(`fus:sharesMeasurementSource`, IMU에서 유도) | 공통 측정원이 있으면 `fus:requiresMethodUnderSharedSource` = CI를 강제한다. 독립 정보합은 명시한 비교 모드에서만 허용한다(`check_method`). |
| 공분산 보고 여부(`fus:hasUncertainty`, `fus:reportedByEstimator`) | 보고된 블록만 그 블록의 CI에 참여한다. 정렬 불확실성은 '보고되지 않음'으로 표시한다. |

## 6. 결정: 공분산의 크기 — **B 채택 (2026-11-18, 사용자)**

- **구현:** log γ_k,b = softplus(log γ_norm,k,b + u_k,b), P̃_k,b = γ_k,b P_k,b (b ∈ 위치·속도·자세).
  - γ_norm,k,b = max_j tr(P_j,b) / tr(P_k,b)는 그 시점에 보고된 값들의 크기를 가장 보수적인 해에 맞추는 기준이다. 보고값만으로 계산하며, 학습 분할에 맞춘 값이 아니다.
  - u는 R-GAT 헤드의 출력이다. u = 0이 'trace 정규화 CI' 비교군이다.
- **γ_norm 기준이 필요한 이유:** 보고 공분산에서 바로 시작하면(γ = 1) LIO가 정보를 독점해 u의 기울기가 사라진다. 스모크에서 확인했다.
- **보장되는 것:** w가 단체(simplex) 위에 있고 γ ≥ 1이므로, 융합 공분산은 보고 공분산으로 한 CI보다 항상 크다(더 보수적).
- **보장되지 않는 것:** 실제 오차와의 일관성. NEES로 따로 검증한다.
- **기준선:** A(`rgat_A`, 표준 CI, 균등 CI)를 함께 평가한다.
