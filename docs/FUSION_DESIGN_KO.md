## 2. 비평 반영 내용

| 비평 | 반영 |
|---|---|
| ① 가중치의 의미 | R-GAT 출력 w는 CI의 **정보 가중치**로 정의한다. 실제 기여도와 융합 불확실성은 따로 계산·보고한다. 실제 기여도 c_k = tr(P_f w_k P_k⁻¹)/3이고, 합은 1이다. [구현·검증] `evaluate.py` |
| ② CI가 정확도를 보장하지 않음 | 정확도(RMSE·p95·최대·RTE)와 공분산 일관성(NEES, χ²₉₅ 초과 비율)을 독립 지표로 둔다. 표준 CI(최소 trace)와 균등 CI를 기준선으로 둔다. [구현·검증] |
| ③ 좌표계 정렬의 공통 오차 | 해들 사이 오차 상관을 분석해 1차 결과를 얻었다(4절). 전역 오차와 지역 오차(10 s 상대 오차 RTE)를 따로 평가한다. 정렬 유효·잔차·나이는 입력 특징으로 유지한다. |
| ④ 학습 가중치는 CI의 보수성을 보장하지 않음 | 주장하지 않는다. 비평의 반례(관측값에 의존하는 가중치)를 문서에 기록하고, 공분산 일관성은 실험으로만 판단한다. |
| ⑤ 온톨로지의 실제 기여 | 온톨로지가 융합 연산에 들어가는 지점은 세 곳이다. 아래 표 참조. 온톨로지 제약을 뺀 그래프(`ontology_constraints=False`)를 비교군으로 둔다. |
| 성분별 차이 | 해 × 블록(위치·속도·자세) 가중치를 쓰는 `head="block"` 변형을 둔다. [구현·검증: 기울기 전달] |
| 진행 순서 | 비평의 권장 순서를 따른다: 정렬·공분산 확인 → 표준 CI 대 선택 → GRU 가중치 → 온톨로지 R-GAT → 공통 센서·복합 결함 → 전체 상태·폐루프 |

온톨로지가 융합 연산에 들어가는 세 지점은 다음과 같다(`ijcas/fusion/ontology.py`).

| 온톨로지 관계 | 융합 연산에 미치는 영향 |
|---|---|
| 추정기의 입력 의존(`:requiresEssential`, `:usesAiding`) | R-GAT의 보호 간선(정의 관계 6개 + 해 → 융합 3개). 필수 입력의 수신 검사는 적격성에서 처리한다. |
| 공통 측정원(`fus:sharesMeasurementSource`, IMU에서 유도) | 공통 측정원이 있으면 `fus:requiresMethodUnderSharedSource` = CI를 강제한다. 독립 정보합은 명시한 비교 모드에서만 허용한다(`check_method`). |
| 공분산 보고 여부(`fus:hasUncertainty`, `fus:reportedByEstimator`) | 보고된 블록만 그 블록의 CI에 참여한다. 정렬 불확실성은 '보고되지 않음'으로 표시한다. |

온톨로지는 실제 오차 상관계수를 알지 못하며, 이 설계는 그 값을 가정하지 않는다.

## 4. 1단계 결과: 실제 공분산과 공통 오차 (스모크 실행 1회, S00 정상 비행, 참고용) [결과]

**공통 오차.** 세 해가 모두 적격인 시점에서 수평 오차의 해 간 상관은 다음과 같다.

| 축 | GNSS/INS–VIO | GNSS/INS–LIO | VIO–LIO |
|---|---|---|---|
| x | 0.81 | 0.80 | 0.95 |
| y | 0.83 | 0.86 | 0.97 |

- 세 해의 단순 평균 RMSE는 0.685 m로, 가장 좋은 단일 해(LIO 0.689 m)와 거의 같다.
- VIO·LIO는 30 s 창으로 PX4에 계속 다시 정렬되므로 PX4의 GNSS 오차를 공유한다.
- 정상 비행에서는 독립적인 위치 정보가 거의 없다.
- 결함 구간(정렬이 얼어 해들이 서로 독립이 되는 구간)에서의 결론은 다회 데이터로 판단한다.

**보고된 공분산의 일관성(위치).**

| 해 | 보고 σ 중앙값 | 오차 중앙값 | 평균 NEES (이상값 3) | χ²₉₅ 초과 |
|---|---|---|---|---|
| GNSS/INS | 0.21 m | 0.62 m | 17 | 54 % |
| VIO | 0.11 m | 0.59 m | 63 | 88 % |
| LIO | 0.0009 m | 0.58 m | 약 580,000 | 100 % |

세 추정기 모두 실제 전역 오차보다 낙관적이다. 정렬 오차는 어느 추정기의 공분산에도 들어 있지 않다.

**비교 방법(같은 실행).**

| 방법 | 위치 | 속도 | 자세 | RTE₁₀ | 위치 기여도(GI, VIO, LIO) |
|---|---|---|---|---|---|
| GNSS/INS 고정 | 0.773 | 0.074 | 1.76° | 0.469 | 1, 0, 0 |
| VIO 고정 | 0.700 | 0.046 | 0.91° | 0.366 | 0, 1, 0 |
| LIO 고정 | 0.689 | 0.054 | 2.12° | 0.346 | 0, 0, 1 |
| 균등 평균(공분산 무시) | **0.685** | **0.040** | 1.27° | **0.300** | — |
| 균등 CI | 0.689 | 0.043 | 2.12° | 0.346 | 0, 0, 1 |
| 표준 CI(최소 trace) | 0.689 | 0.054 | 2.12° | 0.346 | 0, 0, 1 |
| 독립 정보합 | 0.689 | 0.043 | 2.12° | 0.346 | 0, 0, 1 |
| 단일 해 Oracle(참값 사용) | 0.581 | 0.062 | 1.58° | 0.364 | — |

**학습 스모크.** 이 실행의 1,200 tick으로 4 에폭 학습했다.
- 융합 손실이 0.445에서 줄지 않았고 기여도는 LIO 100 %로 고정됐다.
- 이유: LIO의 정보 행렬이 다른 해보다 10⁵–10⁶배 크다. softmax 가중치가 바뀌어도 기여도 c_LIO ≈ 1이 유지되고, 기여도에 대한 기울기가 거의 0이 된다.

**결론(현재 표본 기준).** 실제 공분산을 그대로 쓰는 가중 CI는 사실상 'LIO 고정'이 된다. 학습 가중치가 이를 바꾸지 못한다. 이 문제를 먼저 결정해야 한다(6절).

## 6. 결정이 필요한 것: 공분산의 크기를 무엇이 정하는가

| 선택지 | 내용 | 장점 | 문제 |
|---|---|---|---|
| A. 실제 공분산 그대로(현재) | P_k를 보고값 그대로 쓴다 | 사용자 원칙에 가장 충실 | CI가 LIO 고정이 된다. 학습 효과가 없고, 융합 공분산은 크게 과신한다(NEES 수십만). |
| B. 학습 팽창 계수 γ_k ≥ 1 (비평 제안) | R-GAT가 해별(또는 블록별) γ_k를 상황마다 출력하고 P̃_k = γ_k P_k로 쓴다. log 공간에서 넓은 범위를 허용한다. | 실제 공분산의 형태(성분 비, 교차항)는 유지하면서, 낙관적인 해를 상황에 따라 억제할 수 있다 | 보고값을 학습으로 바꾸는 셈이다. CI의 일관성을 보장하지 않으므로 NEES로 따로 검증해야 한다. |
| C. 공분산의 형태만 사용 | P_k를 크기로 정규화하고, 크기는 가중치가 정한다 | 학습이 쉽다 | 융합 공분산의 크기에 물리적 의미가 없어진다 |

**추천: B를 제안 모델로, A를 기준선으로 함께 평가하는 것이다.**
- 두 모델 모두 정확도와 일관성을 따로 보고한다.
- 이 선택은 '학습 분할로 보정한 고정 대체값' 금지와 다르다. γ는 매 시점 모델이 출력하는 값이고, 보고된 공분산 자체는 기록에 그대로 남는다.
- 다만 사용자 원칙에 저촉되는지는 사용자가 결정한다.
